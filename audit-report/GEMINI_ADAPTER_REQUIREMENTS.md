# Gemini approval boundary: unresolved engineering work

Finding **SEC-012: IMPLEMENTED, NOT VERIFIED against the real CLI** (see "Implemented adapter" below; it stays open until the real-CLI acceptance passes). Before this change: Returning a denial from the current `agy.js` edit notice cannot prevent a mutation that the CLI has already performed. Killing the CLI after the event also cannot establish pre-edit authorization or recover the original bytes.

## Investigated options

The official [Antigravity hooks documentation](https://antigravity.google/docs/hooks/) describes a `PreToolUse` decision hook loaded through user or workspace configuration. CLI 1.3.3's actual help exposes no per-chat settings/hook override. A private mandatory hook immune to project overrides, startup hooks and agent configuration edits has not been verified. The two tested app-data environment overrides did not establish an isolated configured hook; the no-provider-call probe stopped at authentication. This is incomplete verification, not proof that the vendor cannot support an appropriate integration.

The official [SDK policy interface](https://antigravity.google/docs/sdk/policies/) supports application approval callbacks. Its [quickstart](https://antigravity.google/docs/sdk/overview/) uses API-key or Google Cloud authentication. Switching Kural to that interface needs explicit compatibility work for existing CLI login, model selection, saved conversations, attachments, usage, stop/resume and integrations. It is not a validated drop-in replacement. No real credentials or paid provider calls were used.

## Required implementation behavior

- Every tool executes only after a trusted host decision. Map file, shell, web, device, MCP and nested-agent calls to Kural's existing policy. Unknown tools require approval; Ask/Plan deny unknown capabilities until classified.
- The CLI/SDK must wait for the decision. A denial, disconnected host, invalid request, timeout or cancelled chat prevents execution. No provider-side permissive fallback is acceptable.
- Save the checkpoint only after authorization, and finish it before mutation. Keep file contents byte-exact and enforce canonical paths.
- Bind approval to chat, tool arguments and current mode. Reject stale responses after mode changes, handoffs, restarts or cancellation. Nested agents retain the host gate.
- Keep bridge authentication and configuration outside project control. A repository hook, MCP response or model edit must not replace or deactivate the gate. Existing third-party startup hooks require a separate trust decision.
- Preserve the current provider's authentication and conversation features, or present an explicit supported migration. Do not quietly disable Gemini or downgrade its tools to make tests pass.

## Implemented adapter (commit `297944cf5850c3e3cf814ccc05e7aa2d25dadfb0`) — IMPLEMENTED, NOT VERIFIED against the real CLI

Design: a Kural-owned `PreToolUse` hook, not the per-chat config path that was not found.

- **Install** (`extension/lib/ai/agy-gate-host.js` `ensureInstalled`, before every agy spawn): merges `"kural-gate": {"PreToolUse": [{"matcher": "*", "hooks": [{"type": "command", "command": "~/.kural/agy-gate/kural-agy-gate", "timeout": 43200}]}]}` into the global `~/.gemini/antigravity-cli/hooks.json`. Other entries are preserved; the previous file is kept as `hooks.json.kural-backup`; writes are atomic (temp + rename, 0600). A file that is not a JSON object is never overwritten: agy is not started and the chat says why. A changed or removed entry/launcher is restored at the next start. The launcher directory must be a non-symlink, user-owned folder (0700).
- **Launcher / gate** (`kural-agy-gate` → `ELECTRON_RUN_AS_NODE=1 <Kural executable> extension/lib/ai/agy-gate.js`; `.cmd` on Windows): reads the call from stdin (≤1 MB, 15 s), and identifies Kural's agy by `KURAL_AGY_GATE` (set only in the environment of agy processes Kural starts) or, if the hook process does not inherit that environment, by a registry file `~/.kural/agy-gate/conversations/<sha256(conversationId)>.json` written when agy reports its conversation id (before any message is sent). Neither present → no output, exit 0, so the user's own terminal agy keeps its own behaviour (deliberate deviation from "print allow": an explicit allow might bypass agy's own prompts). Kural's agy + socket missing/refused, bad token, malformed input, unexpected reply, timeout (just under the 12 h hook timeout) or a session that ended → `{"decision":"deny","reason":…,"allow_tool":false,"deny_reason":…}`, exit 0. Allow → `{"decision":"allow","allow_tool":true}`.
- **Host** (`GateHost`): private socket in a 0700 temp folder (named pipe on Windows), random 32-byte token per agy process, sha256 lookup + `timingSafeEqual`, one decision per connection, 1 MB request limit, `PreToolUse` only. Sessions end on Stop, restart, process exit, chat close, model/provider switch or handoff (these replace the process) and on a mode change (`revokeGate`); pending requests are answered deny and a late "yes" does not count.
- **Policy** (`AgyAgent.gateDecide` → the chat's `onPermission`, the same `permission-policy.js decide()` and cards as Claude/Codex/Ollama): `gateCall` maps `run_command`/`send_command_input` → Bash (with `Cwd`; outside the project asks even in Auto), `write_to_file` → Write, `replace_file_content`/`multi_replace_file_content` → Edit, `view_file` → Read, `list_dir` → Glob, `grep_search` → Grep, subagent tools → Task (their own calls are gated too), `call_mcp_tool` → `mcp__<server>__<tool>`, `browser_*` → Browser (denied in Ask/Plan), web tools → WebSearch/WebFetch. Unknown tools, and file tools without a path, are `unclassified`: denied in Ask/Plan, a card in Agent **and** Auto. Requests are refused when the chat's mode differs from the mode agy was started for, or no answer is running. Approved writes are checkpointed (byte-exact snapshot) inside `onPermission` before allow is returned. Writes to `~/.gemini`, `~/.kural` and any `.agents/hooks.json` ask even in Auto (`guard`); `danger.js` flags shell writes to them; `paths.js` treats `.agents/` and `.kural/` as run-later.
- **Detection** (`gateMissed`): a changing tool step (Write/Edit/Bash/Browser/MCP/unclassified) that finishes successfully without a matching gate approval in the same agy process stops agy and fails the answer with an explanation. This is after-the-fact detection, not prevention.
- agy's own mode flags are unchanged (second layer): Ask = default, Plan = `--mode plan`, Agent = `--mode accept-edits`, Auto = `--dangerously-skip-permissions`.
- One-shot calls without a chat (Ask, Ctrl+K, commit messages, Get started's test) use a built-in policy: reads inside the given folders only. Side questions deny everything. Chat agy is never started in untrusted workspaces (`startProc`); agy loads `.agents/hooks.json` only in trusted workspaces, and such a hook can add a veto but cannot overrule Kural's deny (any veto blocks) — it can still run its own command, which is a property of trusting the folder.
- `scripts/from-scratch.sh` removes the `kural-gate` entry when it deletes `~/.kural`.
